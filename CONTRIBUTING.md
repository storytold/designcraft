# Contributing to DesignCraft

Before starting a change, read [AGENTS.md](AGENTS.md) for the clean-room, asset, architecture and
verification rules. These apply to human and agent contributions.

## Check existing work

Search [issues](https://github.com/storytold/designcraft/issues) and
[pull requests](https://github.com/storytold/designcraft/pulls) for the problem and the affected
feature. Read the issue comments and linked PRs, including closed PRs: a fix may already be on
`main`, or another contributor may be working on it. Check the current `main` code before
starting a fix. If an open PR covers the change, coordinate there before starting overlapping work.

## Make your scope visible

When taking on an issue, leave a short comment describing the part you are working on, or open a
draft PR linked to the issue. For a change without an issue, open one first with the problem and
proposed scope. Keep that comment or draft up to date if the scope changes or you stop working.

Link the issue from the PR and explain the resulting behavior and verification. Mark the draft
ready for review when the change is complete and the quality gates in [AGENTS.md](AGENTS.md) pass.
